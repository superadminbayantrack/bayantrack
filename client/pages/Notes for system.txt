2.1 Most Influential HCI Guideline Sets
Ben Shneiderman: 8 Golden Rules (Interaction rules)
Jakob Nielsen: 10 Usability Heuristics (Usability evaluation)
Don Norman: Design Principles (Cognitive design, affordances, feedback)
ISO (International Organization for Standardization): ISO 9241 Standards (Effectiveness, Efficiency, Satisfaction)
W3C (World Wide Web Consortium): WCAG Accessibility (POUR principles)
2.2 Ben Shneiderman's 8 Golden Rules
Strive for Consistency: Use consistent terminology, colors, layouts, and actions. Similar tasks should operate in similar ways.
Enable Frequent Users to Use Shortcuts: Use keyboard shortcuts and gesture controls.
Offer Informative Feedback: Every action should produce feedback.
Design Dialogs to Yield Closure: Tasks should have clear beginning, middle, and end. Show confirmation when completed.
Prevent Errors: Use input validation and disable invalid options.
Permit Easy Reversal of Actions: Provide Undo/Redo, Cancel buttons, and Version history.
Support Internal Locus of Control: Users should feel in control, not the system. Avoid unexpected changes.
Reduce Short-Term Memory Load: Use recognition over recall, keep instructions visible, and chunk information.
2.3 Jakob Nielsen's 10 Usability Heuristics
Visibility of System Status: Keep users informed about what is happening.
Match Between System and Real World: Use familiar language and real-world metaphors.
User Control and Freedom: Provide exits and undo options.
Consistency and Standards: Follow platform conventions.
Error Prevention: Prevent problems before they occur.
Recognition Rather Than Recall: Minimize memory burden.
Flexibility and Efficiency of Use: Support both novice and expert users.
Aesthetic and Minimalist Design: Avoid irrelevant information.
Help Users Recognize, Diagnose, and Recover from Errors: Use clear error messages.
Help and Documentation: Provide searchable help when needed.
2.4 Don Norman's Design Principles
Affordance: Design elements should suggest how they are used.
Signifiers: Visual cues indicating where action should occur.
Feedback: Immediate response to actions.
Constraints: Limit possible actions to prevent errors.
Mapping: Clear relationship between control and outcome.
Conceptual Models: Users should understand how the system works.
2.5 WCAG Accessibility Guidelines (POUR)
Perceivable: Information must be presentable in ways users can perceive (available to all senses).
Operable: Interface must be usable via keyboard, users must be able to operate controls.
Understandable: Clear and predictable, content easy to complete.
Robust: Compatible with assistive technologies and different devices.
2.6 Key Practical HCI Guidelines
Interface Design: Use visual hierarchy, maintain alignment.
Form Design: Use whitespace effectively, maintain color contrast, group related fields, use inline validation, provide clear error messages, mark required fields clearly.
Navigation Design: Keep navigation consistent, use breadcrumbs, provide search functionality.
Mobile HCI Guidelines: Touch-friendly targets, avoid hover-only interactions, use responsive layouts.
2.7 Good Error Message Components
State what happened: Clearly indicate the error.
Explain why: Give the reason for the error.
Provide solution: Tell the user how to fix it.
Avoid technical jargon: Use plain language (e.g., 'Password must be 8 characters' instead of 'Error 0x00021').
2.8 Steps in User-Centered Design (UCD)
Involve Users in the Design Process: Include users from the start, gather feedback to shape the system.
Understand User Needs: Conduct user research (interviews, surveys) to understand goals, tasks, problems.
Iterative Design: Create prototypes, test, gather feedback, refine to identify usability issues early.
2.9 Criteria Categories for HCI Guidelines
Age/Generation: Design considering age demographics.
Gender: Design considering gender preferences.
Disability: Design for accessibility.
Country: Design for cultural and regional differences.
Consumer: Design for consumer types.
Occupation: Design based on professional usage.
2.10 Usability Criteria
Learnability: How easy to begin using system with little/no training. Helpful instructions/onboarding.
Efficiency: Time or effort required. Reduces unnecessary steps/actions.
Memorability: Easy to remember how to use after a break. Intuitive for occasional users.
Error Handling: How system helps users recover from errors.
Satisfaction: How pleasant the system is to use.
Error Prevention and Recovery: Can users avoid mistakes or recover easily?
Effectiveness: How well system supports achieving goals accurately and completely.
2.11 UI / UCD Criteria
Consistency: Keep similar actions and layouts predictable.
Feedback: System provides immediate feedback for user action.
Affordance: Controls suggest their function.
Flexible/Customizable: System adapts to different users needs.
User Involvement: Users are involved in requirements gathering and testing.
Accessible: Accommodate users with different abilities.
Perceivable: Information must be available to all senses.
Operable: Users must be able to operate controls.
Understandable: Content must be easy to complete.
Robust: Works across different devices and assistive technologies.
2.12 Cognitive and Psychological Criteria
Minimizing cognitive load: Avoid confusing layouts, unnecessary options or complex jargon.
Physical ergonomics: The interface should not strain the body.
Match with Real World: Use familiar concepts and language.
Recognition over Recall: Show options rather than asking users to remember command.
Error Tolerance: Minimize consequences of mistakes.
Minimalist Design: Avoid unnecessary complexity.
2.13 Aesthetic and Design Criteria
Visual Clarity: Clear/readable fonts, proper contrast, intuitive layout.
Consistency in Design: Similar colors, fonts, layouts across application.
Emotional Design: Engages users through enjoyable or satisfying interactions.
Aesthetic Design: Visually appealing interfaces increase satisfaction.
Motivation and Engagement: Encourage continued use.
2.14 Safety and Security Elements
Protection: Designs must consider user safety, data privacy, and preventing harm.
Authentication: Example: Two-factor authentication for online banking.
Warning Dialogs: For destructive actions, like deleting files permanently.
Dark Mode: To reduce eye strain at night.
2.15 Key Principles of Visual Display Layout
Clarity and Readability: Text easy to read (legible fonts, size, contrast). Use spacing to reduce clutter.
Consistency: Keep layout consistent across screens to build familiarity.
Visual Hierarchy: Arrange elements to guide attention using size, color, contrast, position.
Alignment and Grid Use: Use grid systems to align elements neatly for an organized look.
Grouping and Proximity: Group related elements; close elements are perceived as related.
Whitespace (Negative Space): Space around elements improves focus, reduces visual noise, avoids cramming.
Balance and Symmetry: Distribute elements evenly for a balanced feel (symmetrical or asymmetrical).
Navigation Placement: Main navigation easily visible/accessible (top or left). Familiar placement.
Color and Contrast: Use color to differentiate and draw attention. Ensure accessibility contrast.
Responsiveness and Adaptability: Layout must adjust for screen sizes (mobile, tablet, desktop).
2.16 Hierarchy and Structure Details
Primary Information: Most important elements (main buttons, critical info) should be larger, prominent, highlighted with contrast.
Secondary Information: Less critical content (secondary actions, less urgent details) visually downplayed via smaller fonts/subtler colors.
2.17 Navigation and Placement Elements
Navigation Bar: Prominently placed (top/side) and consistent across the system.
Breadcrumbs: Trace navigation path in complex systems.
Search Bar: Easy to locate, typically placed at the top.
Call-to-Action (CTA): Important buttons stand out using color, size, positioning.
2.18 Typography Rules
Readability: Body font size of 16px (on web) or slightly larger is ideal.
Contrast: Sufficient contrast between text and background for visually impaired users.
Font Families: Stick to limited number (2-3) for visual harmony. Use weights and sizes to differentiate.
2.19 Color and Contrast Rules
Color Palette: Reflects brand/purpose, harmonious, avoid clashing/overly bright colors.
Contrast for Accessibility: Don't convey important info through color alone (color blindness).
Color Coding: Red for errors, Green for success. Must provide text labels for color blindness.
